# 过程记录技能（Process Record）

用于在长程任务完成后撰写过程记录。**只写过程与经验，不重复结果本身**（结果放最终回复即可）。

## 步骤

1. 回顾本次任务的关键步骤与踩坑点（对照会话中的失败→排查→解决序列）
2. 按下方模板撰写，保存为 `docs/03-dev/process-records/YYYY-MM-DD-<简述>.md`（简述用 kebab-case 英文）
3. 在最终回复中附上该文件的链接（格式 `` `docs/03-dev/process-records/<文件名>` ``）

## 模板

```markdown
# <日期> <任务简述>

## 任务概述
- 目标：…
- 结果：…

## 过程简述（关键步骤 3~8 条）
1. …

## 遇到的问题
### 问题 1：<标题>
- **现象**：…
- **原因**：…（要挖到根，禁止只写"改好了"）
- **解决**：…
### 问题 2：…

## 最耗时项
- <项>：约 <时长>。原因与教训：…

## 最耗 token 项
- <项>：原因与教训：…

## 规避与完善方案（给后续会话）
- [ ] 可执行的动作，如"用 X 代替 Y"、"先探测 Z"

## 相关文件 / 提交
- 提交：<hash> <message>
- 涉及文件：…
```

## 写作要点

- **现象→原因→解决 三段式**，原因挖到根（环境？沙箱？版本？竞态？）
- **耗时/耗 token 诚实写**：指出浪费在哪一步、为什么，才能改进工作方式
- **规避方案写成可执行动作**（"后续做 X"），不要写"以后注意"
- 中文撰写；参考现有记录：`docs/03-dev/process-records/2026-08-25-env-build-setup.md`

## 关联

- 完整约定：`docs/03-dev/process-recording.md`（DSH 项目记忆 `AGENTS.md` 里有摘要）
- Bug 类问题走 `docs/03-dev/bugs/BUG-xxx.md`，过程记录不替代 bug 跟踪
