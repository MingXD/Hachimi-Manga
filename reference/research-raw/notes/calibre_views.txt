Purpose and Scope 
 This document describes Calibre's library browsing and navigation systems, which provide multiple ways for users to view and filter their book collection. The system consists of three main components: the book list views (table, grid, and bookshelf layouts), the tag browser for category-based navigation, and the search/filtering system including virtual libraries. 
 For information about metadata editing and book details display, see Book Details and Metadata Editing . For the database system that powers these views, see Database Cache and API .

 Calibre supports a rich query language: 
Query Type Syntax Example Simple text word asimov (searches all fields) Field-specific field:value authors:asimov Phrase search "exact phrase" title:"foundation series" Boolean AND OR NOT authors:asimov AND series:foundation Comparison >= <= = != rating:>=4 Regular expression field:~pattern title:~robot.* Set membership field:=value tags:=fiction (exact match)

 Virtual Libraries 
 Virtual Libraries are named, persistent search restrictions that filter the entire library view. 
Virtual Library Operations: 
Operation Method Effect Create VL create_virtual_library() Saves search as named VL Apply VL apply_virtual_library(name) Filters all views to matching books Clear VL apply_virtual_library() (no name) Shows all books Edit VL edit_virtual_library() Modifies search query Delete VL delete_virtual_library() Removes saved VL 
 Virtual libraries affect: 
Book list views (only shows matching books) 
 Tag browser counts (only counts books in VL) 
 Search scope (searches within VL) 
 Bulk operations (applies only to VL books) 
The active VL is stored in db.new_api.pref('virtual_lib_on_startup') for persistence.

Performance Optimization 
 The view system includes several optimizations for handling large libraries: 
 Lazy Loading and Caching 
Optimization Techniques: 
Buffered Row Loading : Only data for visible + buffer rows is fetched 
 Cover Thumbnail Cache : Thumbnails are generated once and cached 
 Debounced Recounts : Tag browser counts are recalculated with delay to batch updates 
 Icon Caching : Emblem icons are rendered once per unique combination 
 Zero-Page Count Caching : Page count display is debounced to avoid slow queries

Integration with Main Window 
 The navigation components are integrated into the main window through the LayoutMixin and related initialization: 
The initialization sequence in Main.initialize() : 
Create database cache 
 Initialize interface actions 
 Call LayoutMixin.init_layout_mixin() to create widgets 
 Call LibraryViewMixin.init_library_view_mixin() to set up book views 
 Call TagBrowserMixin.init_tag_browser_mixin() to set up tag browser 
 Call SearchBoxMixin.init_search_box_mixin() to set up search 
 Connect signals between components 
 Restore saved state
