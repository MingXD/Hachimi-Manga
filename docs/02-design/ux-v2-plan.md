## 一、文件系统：混合展示（文件夹 + 漫画）—— 目录浏览器模式

### 现状与问题
- 侧边栏 TreeView 选中目录 → 右侧**只显示该目录里的书**（BookItemViewModel 封面墙），
  子文件夹不展示；想看 B 里的子文件夹只能靠侧边栏树逐级点。
- 用户期望（A/B/C/D 案例）：右侧同时展示 **B（文件夹样式）、C、D（漫画封面样式）**，
  双击 B 进入下一层，双击 C/D 直接打开漫画。

### 方案：右侧内容区改为「目录浏览器」
1. **统一条目模型** FolderEntryItemViewModel：
   - `Type = Folder | Book`
   - Folder：名称、子项数（子文件夹+书）、文件夹图标样式（无封面，用文件夹图形/名称卡片）
   - Book：复用现有封面墙样式（缩略图 + 名称 + 页数）
2. **内容区展示**（封面墙位置改造）：
   - 展示当前目录的 `Children`（文件夹）+ `Books`（漫画），文件夹在前
   - 双击文件夹 → 进入下一层（内容区刷新为该层）；双击漫画 → 打开阅读器
   - 面包屑导航栏（顶部）：当前路径各层可点击回退；"⬆ 上级"按钮
3. **侧边栏 TreeView 保留**：选中节点 → 右侧内容区同步展示该层（双向一致）；
   选中目录时同样走"混合展示"而非只显示书
4. **文件操作**：漫画右键菜单保留（打开/资源管理器/重命名/删除/属性）；
   文件夹右键加"在资源管理器中显示"（后续可加重命名/删除）
5. **搜索**：搜索仍基于整个库（不因目录变化而失效）

### 改动范围
- Core：FolderNode 已含 Children+Books（够用，无需改）
- App：新增 FolderEntryItemViewModel；MainWindowViewModel 增加 CurrentFolder +
  EnterFolder/GoUp/面包屑逻辑；MainWindow.axaml 内容区改为 ListBox 混合模板
  （DataTemplate 按 Type 选样式）+ 面包屑栏

## 二、Webtoon 滚动模式重构（参考 mihon/Tachiyomi WebtoonViewer）

### 现状与问题（"完全不可用"）
1. **滚动极慢**：滚轮 `_ty -= e.Delta.Y * 3.0` 依赖 Delta 数值 —— 与早期缩放慢
   同根因（Avalonia #9858：Delta 值间歇性极小/不稳定）→ 每滚一格几乎不动
2. **每帧全量重建**：`UpdateWebtoonPages` 每次滚动 Clear 整个面板再 await 逐页
   重新解码 → 卡顿、闪烁
3. 页面上下拼接 OK（Uniform 高度一致 = BaseH×scale），但无虚拟化、无预加载
4. 无拖拽、无 Ctrl+滚轮缩放

### 调研结论（mihon WebtoonViewer）
- RecyclerView 虚拟化：**只保留可见页 holder，回收复用**，滚动流畅
- 预加载相邻页（当前页 ±4，优先级队列）
- 滚动距离按事件/物理量，与滚轮速度同步

### 方案（Avalonia 实现）
1. **虚拟化渲染（核心）**：
   - Webtoon 面板高度 = 总页数 × 页高（页高 = BaseH×scale，每页高度一致 → 上下无缝）
   - 只实例化**可见范围 ±2 页**的 Image；维护 `Dictionary<int,Image>`，
     滚动时增量 Add/Remove（复用现有 Image 对象，只换 Source 与位置），**不再 Clear 重建**
   - 页位置：绝对定位（Panel.Margin.Top = i×页高）或 Canvas.Top
2. **滚轮按事件计数滚动（修复慢）**：每次滚轮事件 = 固定步长（如 96px × 灵敏度，
   方向按 Delta 符号）——与分页模式缩放修复同思路
3. **Ctrl+滚轮 = 缩放**：复用 ZoomToFocus（锚定鼠标，同分页模式）；缩放后页高变化，
   重算虚拟化范围并保持锚点
4. **鼠标拖拽平移**：复用现有 PointerMoved 拖拽（Webtoon 模式也允许拖 _ty，
   空白不拖）；拖动中增量更新虚拟化
5. **滚动边界 Clamp**：_ty ∈ [-总高+视口高, 0]（内容不足视口时贴顶）
6. **当前页指示**：滚动时计算可见页号 → 更新 PageText（供进度条用）
7. **预解码**：可见范围确定后，异步预解码 ±2 页（复用现有 DecodeAsync 缓存 +
   UI 引用计数 BUG-004 机制，不重复分配）
8. 可选（后续）：tap 区域翻页（mihon 3/4 屏），首版不做避免误触

### 性能目标
- 滚动流畅（按事件计数 + 虚拟化增量，无每帧全量重建）
- 内存可控（只保可见 ±2 页 + LRU 缓存 6 页）

## 三、快速翻页（长漫画几百页 → 从任意页开始）

### 调研结论
- **KOReader**：底部主状态栏进度条；tap-and-hold 调出 **Skim 对话框**
  （拖动进度条实时跳页、TOC 章节标记）；滑条支持章节级跳跃
- **mihon/Tachiyomi**：跳页对话框（页码输入）+ 部分客户端缩略图网格预览
- 共性：**进度条拖动 + 页码直接输入** 是长文档标配；缩略图预览是增强

### 方案（分层落地）
1. **底部进度条（v1.7 首版）**：
   - 分页模式：底部细进度条（Slider 0..TotalLogical-1），拖动时实时显示目标页号，
     松开跳转（拖动过程中不逐页解码，避免卡顿）
   - Webtoon 模式：进度条映射物理页位置，拖动滚动到对应页
2. **页码跳转对话框（v1.7）**：
   - 按 `G` 或点击工具栏页码文本 → 输入框（"跳转到第 N 页（共 M 页）"）→ 回车跳转
   - 兼容逻辑页/物理页（双页模式提示逻辑页）
3. **（M3 增强，可选）缩略图预览条**：悬停/拖动进度条时显示附近几页缩略图
   （复用 ThumbnailService 小图解码），需要时再做

### 交互细节
- 进度条仅在阅读器底部，窄条（高 6px）不遮挡画面，鼠标悬停变高便于拖动
- 书签（B 键已有）与进度条互补：书签跳到指定书签，进度条自由拖动

## 四、日志与协作方式（后续 bug 排查流程）

### 现状
- App.SLog 已写 LocalAppData/MangaAgent/app-start.log（含全局 CRASH 记录）
- --diag 自动诊断已存在

### 方案
1. **结构化操作日志**：阅读器记录关键事件（打开书/翻页/缩放/模式切换/滚轮 Delta 采样/
   滚动位置/虚拟化范围），带时间戳与线程号 → 排查"操作类 bug"时有完整轨迹
2. **日志轮转**：按日期分文件（app-2026-08-20.log），保留最近 7 天，避免无限增长
3. **--diag 增强**：自动执行操作序列（打开→翻页→缩放→模式切换→滚动）输出
   状态快照，与真实用户操作互证
4. **协作流程（约定）**：
   - 我提供：精确操作步骤（点哪、按什么键、期望什么）
   - 用户执行后回传：`%LOCALAPPDATA%\MangaAgent\app-start.log` + 截图
     （或描述现象：画面位置/是否卡死/报错文本）
   - 我依据日志轨迹 + 截图分析定位，不再依赖"我远程截图"
5. 对图像类 bug：提供"像素坐标自检"手段（如缩放锚点自测），用户按步骤操作后
   回传日志中的数值，我对比理论值定位
