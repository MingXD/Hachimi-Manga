# BUG-001：阅读器画面全空（能操作但看不到图） — 已修复 ✅

- **状态**：已修复并验证（2026-02）
- **优先级**：高

## 现象
双击打开漫画后，翻页等操作正常，但阅读区**看不到画面**（纯背景色）。

## 原因（调查确认）
1. 真实应用渲染/解码本身正常（夹具 PNG、2500×3500 JPEG、300 页书均验证渲染成功）。
2. **代码缺陷**：`ReaderViewModel.DecodeAsync` 每次翻页全尺寸解码且**无缓存、旧位图不释放**，
   解码异常被 try/catch **静默吞掉** → 在内存紧张机器（实测仅剩 ~2.7GB）上，大图翻几页后
   解码失败/内存累积 → Image1=null → **纯空白且无任何提示**。

## 修复（两轮）
第一轮（内存控制）：
1. 页面位图 LRU 缓存（上限 6 页），淘汰即 Dispose。
2. 解码失败显示提示条。
第二轮（真根因：按显示尺寸降采样解码）：
3. **`Bitmap.DecodeToWidth` 按需降采样**：解码目标宽度 = 视口×缩放×DPI（上限 4096，
   下限 1600）→ 4K 扫描页位图从 104MB → ~10MB。
4. **翻页竞态防护**：加载序号 guard，旧页解码完成不再覆盖当前页。
5. **JPEG 头部解析增强**：SOF 扫描缓冲 64B → 64KB（大图 APP 段长，取准确宽高比）。
6. 说明：Headless 平台 DecodeToWidth 有 w×w 伪影（测试限制），真实应用正常
   （缩略图同路径已验证）。

## 验证（实测）
第一轮：夹具/JPEG/300 页书渲染正常；内存稳定 ~159MB；18/18 测试通过。
**第二轮（用户真实文件 test-file：38 张 4299×6071 JPEG）**：
- 修复前：打开长时间空白（全尺寸解码 104MB/页，内存紧张时慢/失败）
- 修复后：**--open 打开 2 秒内出图**（light 28.1%），内存 159MB
- 测试 18/18 通过
