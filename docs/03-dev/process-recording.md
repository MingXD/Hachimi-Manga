# 长程任务过程记录约定

> 2026-08-25 定稿（主开发 v2 会话，用户要求）。
> 目的：长程任务（构建、修 Bug、加功能、多轮调研）**除了结果，还必须沉淀"过程"**——遇到什么问题、原因、怎么解决、什么最耗时、什么最耗 token、后续如何规避。让下一个会话/新 Agent 不必重新踩坑。

---

## 1. 什么时候写

以下任务完成后，最终回复里**必须附一份过程记录**（文件链接）：

- 所有**长程任务**（goal 驱动的多轮任务、需要跨多步完成的任务）
- 单轮内**踩过坑**的任务（构建/测试失败、环境问题、工具链问题等）
- 用户明确要求"记录一下/记入流程"的任务

简单单轮任务（如改一行配置）不强制，但踩坑了仍建议写。

## 2. 写到哪里、怎么命名

- 目录：`docs/03-dev/process-records/`
- 命名：`YYYY-MM-DD-<简述>.md`，简述用 kebab-case 英文（例：`2026-08-25-env-build-setup.md`）
- 已有记录见目录索引；与 `bugs/`（Bug 现象/复现/修复）、`vX-changes-record.md`（版本功能变更）**分工不同**：本目录沉淀"**过程与经验**"（含环境、工具、协作类问题，bug 之外的一切踩坑）。

## 3. 模板（字段说明）

```markdown
# <日期> <任务简述>

## 任务概述
- 目标：…
- 结果：…（构建 0 错误 / 测试 N/N 通过 / 功能完成等）

## 过程简述（关键步骤，3~8 条）
1. …
2. …

## 遇到的问题
### 问题 1：<标题>
- **现象**：…
- **原因**：…
- **解决**：…
### 问题 2：…
（没有则写"无"）

## 最耗时项
- <项>：约 <时长>。原因与教训：…

## 最耗 token 项
- <项>：原因与教训：…

## 规避与完善方案（给后续会话）
- [ ] …

## 相关文件 / 提交
- 提交：<hash> <message>
- 涉及文件：…
```

## 4. 写的时候注意

- **原因要挖到根**：现象→原因→解决 三段式，禁止只写"改好了"
- **耗时/耗 token 要诚实**：写清楚哪一步浪费了时间/token、为什么（便于后续优化工作方式）
- **规避方案要可执行**：写成"后续做 X"而不是"以后注意"
- 中文撰写（与仓库其他文档一致）

## 5. 与 DSH 记忆机制的衔接

- 本项目根目录有 `AGENTS.md`（DSH 自动加载的项目级指令），内含工作流要点与**本约定的摘要**；新会话开始时模型会自动看到
- `.dsh/skills/process-record/SKILL.md` 是"过程记录"技能：长任务收尾时按需加载，内含模板与写作指引
- 因此约定分三层：AGENTS.md（常驻记忆，摘要）→ process-recording.md（完整约定）→ process-records/（实际记录）
