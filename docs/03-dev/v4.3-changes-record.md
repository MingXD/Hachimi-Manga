> 对应方案 `docs/03-dev/v4.3-plan.md`。测试基线：**119 → 132/132 全绿**（+13）。

## 1. 右键多选（bug 修复）

- 根因：右键菜单每项 = 条目自身命令（单条），不感知列表多选（多选仅键盘 Delete/Ctrl+C/X 生效）
- 修复：
  - `MainWindow.axaml` 两处菜单 `Command` → `Click`（Tag 标记动作），`MainWindow.axaml.cs` 新增 `OnEntryMenuClick` 统一分发：
    - **多选感知**：右键项不在选区 → 先单选它（文件管理器行为）；在选区 → 对全部选中项执行
    - 复制到…/移动到…/删除 = **批量**（`MainWindowViewModel.CopyPathsToAsync/MovePathsToAsync` 新增逐项进度 + 失败汇总；删除复用 `DeletePaths`，**>1 项弹确认**）
    - 打开/重命名/属性 = 仅单选；在资源管理器中显示 = 多选打首个
- 测试：`MultiSelectTests`（批量复制/移动/删除真实文件；缺失路径跳过+状态文案）

## 2. webp 漫画页显示极小（bug 修复）

- 根因（实测用户库 56 页 webp）：`ImageInfo.ParseWebp` 的 **VP8 有损分支解析错位**——从 start code（9D 01 2A）读宽度、误用 VP8L 位打包公式 → 1280×1899 被解析成 **414×169**（比例 2.45）→ 被当横向页单拼且显示极小
- 修复：VP8 按规范 `w = data[6]|(data[7]&0x3F)<<8`、`h = data[8]|(data[9]&0x3F)<<8`；补齐长度检查与 0 尺寸保护
- 回归：`ImageInfoWebpTests`（VP8/VP8L/VP8X 程序化头部 + 真实 1280×1899 样本 fixture `reference/fixtures/webp/`）；真实库 56 页全部解析为竖版（1280×1853~2048，ratio 0.63–0.69）

## 3. 文件夹自定义封面（新功能）

- 数据：`reading.db` 新表 `FolderCovers(FolderPath, RelPath, UpdatedAt)`——**只存记录，不写文件夹/图片任何属性**；`ReadingStateStore` 新增 `ValidateFolderCoverRelPath / SetFolderCover / LoadFolderCover / LoadFolderCovers(批量) / ClearFolderCover`
- 校验：相对路径不含 `..`、解析后必须落在文件夹内、图片扩展名、文件存在
- UI：

  - 卡片模式封面区：**比漫画封面矮一档**（大图 216×232 / 中图 144×155 / 小图 96×100，为三行文本留空间），`UniformToFill`；无封面/失效回退原 📁 图标；**名称/子文件夹数/漫画数文本完全保留**
  - 目录加载时批量查询封面（一次 SQL）+ 前 24 条懒加载缩略图（`ThumbnailService.GetImageThumbAsync` 新增任意图片缩略图）
- 测试：`FolderCoverTests`（路径校验 7 种形态 / 存储往返 / 批量 / 清除 / 条目显示-清除回退-非法封面不生效）

## 4. 配对起点 1/2 强制配对（行为变更）

- 根因（用户观察"配对起点 1/2 完全一样、永远单拼"）：
  - 左对右规则冲突：`SpreadThreshold=1.6` 宽页单页 + 封面单页 → 若第 2 张为宽页，起点 1 的 (1,2) 被拆开 → 与起点 2 的 (2,3) 结果相同
  - webp 书更典型：比例解析 bug 让每页都成"横向页"→ 每页单拼（本次已修）
- 修复：`PageLayoutOptions.ForcePairing`（阅读器固定 true）：
  - 起点 1 → **(1,2)、(3,4)…**（封面页也参与配对）
  - 起点 2 → **第 1 张单页**，(2,3)、(4,5)…
  - **忽略页面宽高/封面规则**；末张不足单页
- 测试：`PageLayouterTests` 4 个 ForcePairing 用例；同步更新既有双页断言（`ReaderE2eTests` 续读/书签映射、`QuickJumpTests` 逻辑→物理映射 199、`BugDiagnosticsTests` 单页模式翻页按物理推进）
