# 清晰度 × 缓存 综合方案（流畅 + 清晰阅读体验）

> 2026-08-25。目的：让"连续翻页流畅"与"放大后清晰"兼得，并把关键选项做进设置，用户按自己设备性能决策。
> 状态：**调研 + 方案，未实施**。待用户探讨决策。

## 一、现状全链路（调研结论）

### 1.1 解码宽度怎么定的
```
显示需求 = 当前显示内容宽度 × 屏幕 DPI（RenderScaling）
解码宽度 = clamp(显示需求, 1200, 上限 2048)      ← 分页（Canvas.cs）
          clamp(滚动条宽 × scale × DPI, 400, max(1200, 2048))  ← 滚动（Webtoon.cs）
```
- 默认视图本页显示宽 ≈ 560px → 解码 1200px → **缩小显示，永远清晰** ✓
- **上限 2048 是"放大后不清晰"的第一真凶**：4K 原图（4000px 宽）放大超过约 2.5× 后，需求 > 2048 被钳住 → 刷了也糊

### 1.2 缓存与预取
- `_pageCache`：一个物理页一张位图（分页/滚动共享），`_pageCacheWidth` 记录每张的解码宽度
- **预取已有**：翻页后 `PrefetchNeighborsAsync` 预解码相邻页（单页 ±1、双页下一逻辑页），宽度 = 当前 DecodeTargetWidth
- 缓存上限 `CacheCap`（默认 10，设置 4~30），LRU 淘汰，UI 引用保护（BUG-004）
- 短板：①预取范围小（±1，连翻追不上）②**缩放后相邻页缓存仍旧宽度**（放大后翻页又糊又卡）③跳页/Home/End/预览栏跳转无预取 ④预取无并发限流

### 1.3 内存估算（4 字节/像素）
| 场景 | 单张位图 | 缓存 10 张 |
|---|---|---|
| 默认 1200px 解码（单行本） | ~14MB | ~140MB |
| 2048px（现上限） | ~24MB | ~240MB |
| 4K 原图（4000×6000） | **~96MB** | **~960MB（危险）** |
| 4096 限幅（4K 页） | ~100MB | ~1GB（需降缓存数） |

**结论**：原图全尺寸 = 清晰度天花板，但内存峰值巨大——必须用"按需"策略（只有放大到原图级别才解大图）+ 缓存数联动，才能既清晰又不爆内存。

### 1.4 用户感知的"卡/糊"来源
1. 翻页卡：目标页未缓存（连翻 ±1 追不上 / 跳页无预取）→ 现场解码几十~几百 ms
2. 放大糊：2048 上限（刷了也糊）+ 重解码延迟（放大→糊→重解→清晰，中间糊）
3. 放大后翻页又糊：相邻页缓存旧宽度，翻过去重解码

## 二、综合方案（三部分联动）

### 2.1 解码宽度决策升级（清晰度档位，设置下拉）
```
有效上限 = 按档位：
  自动（推荐） = min(原图宽, 4096 安全上限)
  限幅 N      = N（2048 / 4096 自定义）
  原图全尺寸  = 原图宽（最清晰，内存大）
want = clamp(显示需求, 1200, 有效上限)
```
- 原图宽来自 `_sizes`（打开书已全量解析，个别失败回退 4096/显示需求×2）
- 自动档 = 平时小图（快、省内存）→ 放大到原图级别才解大图（配合缓存淘汰，内存峰值可控）

### 2.2 预取强化（流畅度，设置）
| 项 | 现状 | 方案 |
|---|---|---|
| 预取范围 | ±1 | 可设：±1 / **±2（默认）** / ±3 |
| 跳页预取 | 无 | 跳页/预览栏/Home/End/书签后立即预取目标页邻页 |
| **缩放联动** | 无 | 缩放/适应模式变化后，按**新宽度**重预取邻页（限流防风暴）——放大后翻页不再糊 |
| 并发限流 | 无 | SemaphoreSlim(2)（滚动模式已有先例）|

### 2.3 缓存与内存控制
- `CacheCap` 保留设置（4~30）
- 设置界面按"档位 + 缓存数"显示**最坏内存估算**（如"当前配置最坏约 400MB"），档位联动建议缓存数
- 原图/4096 档时提示"建议降低缓存页数"

### 2.4 设置 UI：三档预设 + 高级自定义
**"阅读性能预设"一键选择**（写入 settings.json）：
| 预设 | 解码上限 | 预取范围 | 缓存数 | 适合 |
|---|---|---|---|---|
| 流畅优先 | 2048 | ±1 | 8 | 低配（4~8GB）/ 只看默认视图 |
| **均衡（默认）** | 自动(≤4096) | ±2 | 12 | 主流（8~16GB）|
| 清晰优先 | 原图全尺寸 | ±3 | 16 | 高配（16GB+）/ 重度放大阅读 |

高级项可微调：解码上限（三档 + 自定义）、预取范围、缓存页数（已有）、两阶段模糊优先（默认关，可选开）

### 2.5 两阶段"模糊优先"定位
**默认不做**——预缓存强化后，连续翻页命中缓存即清晰；模糊优先只对"首次打开超大图/跳远页"有边际价值。做成**可选开关**（默认关），需要的用户开启。

## 三、预期效果
- 连续翻页：预取命中 → 瞬时清晰（±2 覆盖快速连翻）
- 放大：自动重解码到原图级（无 2048 钳制）→ 任意倍率清晰；缩放联动让放大后翻页也清晰
- 内存：均衡档自动模式平时 ~150MB（小图缓存），放大峰值由 LRU + 提示控制

## 四、工作量与风险
- Decode.cs（宽度决策 + 预取强化 + 限流）：~150 行
- Canvas/Webtoon want 计算接入 + 缩放联动：~60 行
- Settings（字段 + 预设 UI + 内存提示）：~130 行
- 测试（解码宽度断言/预取范围/预设往返）：~100 行
- 风险：原图档内存（用提示 + CacheCap 兜底）；缩放联动预取风暴（限流）；`_sizes` 缺失回退
