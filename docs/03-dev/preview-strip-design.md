# 底部悬浮预览栏方案设计（2026-08-22）

> 方向：进度条 + 缩略图融合为"底部悬浮预览栏"。用户指定设计方向 + 成熟项目调研（Tachiyomi/KOReader）。
> 状态：待对齐后实施。

---

## 一、现状问题

1. 进度条拖动卡顿/崩溃：ValueChanged 每格触发跳转+解码风暴（_sliderDragging 未接线）
2. 进度条拖动"不知去哪"：无视觉反馈，尤其滚动模式画面跳走
3. 缩略图栏：按钮唤出后只有框没图（ThumbnailService 解码问题），且是 Popup 遮挡
4. 底部常驻进度条：占用画面空间

## 二、用户设计方向（已明确）

- 平时底部无任何东西（画面最大化）
- 鼠标移到底部边缘 → 浮现半透明预览栏
- 预览栏 = 一排缩略图 + 左右翻页键 + 滚轮控制缩略图前后翻
- 每张缩略图显示页码（知道翻到哪）
- 点击缩略图 = 跳转（融合进度条功能）
- 匹配三种显示模式（单页/双页/滚动）

## 三、调研结论（成熟项目做法）

| 项目 | 做法 | 可借鉴 |
|---|---|---|
| KOReader Skim | 长按进度条唤出 skim 对话框：拖动进度条 + 显示目标页 | 隐藏/唤出模式、页码反馈 |
| Tachiyomi 系列 | 无常驻进度条；长按页面唤出页码选择器（缩略图网格） | 缩略图网格跳页 |
| mihon | 进度条 + 页码指示 | 页码显示 |
| Comic viewers (Strips/ReadEra) | 底部边缘悬停唤出缩略图条 | 悬停触发、横向滚动条 |

共性：平时隐藏 + 边缘触发 + 缩略图+页码 + 点击跳转。与用户方向一致。

## 四、设计方案

### 1. 触发方式（悬停唤出）
- 鼠标在阅读区底部边缘（底部 24px 热区）停留 >= 400ms → 预览栏滑入
- 鼠标移出预览栏 + 底部热区 → 300ms 后滑出
- 避免误触：点击阅读区中间区域不触发，仅底部热区

### 2. 预览栏布局（底部悬浮，半透明）
   ◀  [缩略图][缩略图][缩略图][当前][缩略图][缩略图]...  ▶
      P12    P13    P14   ★P15   P16   P17
- 一排 **固定 7 张**，当前页居中高亮（边框+放大一点）
- 每张下方页码（P15）
- 左右 ◀ ▶ 按钮：**整排平移（±7 页）**
- 鼠标滚轮在预览栏上 → 整排前后翻页
- 半透明深色背景，不遮挡过多
- **缩略图尺寸自适应窗口**：预览栏覆盖整个宽度，每张宽 = 窗口宽/7，高按图片比例（窗口大图大、小图小）

### 3. 缩略图数据（性能关键）
- 复用 ThumbnailService（弱引用缓存）——但现有实现有问题（见问题排查）
- 只解码可见的 7-9 张（虚拟化：滚动/翻页时增量加载当前 ±5）
- 小尺寸（如 96x136 或 72x100）：解码目标宽度 ~200px（快）
- 滚动模式：缩略图按物理页映射（前缀和定位已具备）

### 4. 三种模式映射
| 模式 | 缩略图内容 | 点击跳转 |
|---|---|---|
| 单页 | 物理页 ±4 | JumpToPhysical（逐物理页） |
| 双页 | 逻辑页 ±4（每缩略图=一逻辑页，宽图） | JumpToLogical（配对显示） |
| 滚动 | 物理页 ±4 | ScrollWebtoonToPhysical（滚动定位） |

### 5. 进度条融合
- 预览栏本身 = 进度指示（当前页居中 + 页码）
- 可拖动缩略图排（按住左右拖动 = 快速扫描，实时更新页码/缩略图）
- 不再需要单独 Slider

## 五、关键问题排查（实施前必须解决）

### 问题 A：进度条拖动卡顿/崩溃
- 根因：ValueChanged 未防抖 + _sliderDragging 未接线（每次拖动触发解码风暴）
- 新设计天然规避：拖动缩略图排 = 只更新页码 + 加载可见缩略图（小图快），松手才跳转

### 问题 B：缩略图"只有框没图"
- 需排查 ThumbnailService：可能解码失败（headless 限制？真实环境异常？）
- 方案：缩略图用独立小解码（DecodeToWidth ~200），异常降级为"页码占位符"（不白框）
