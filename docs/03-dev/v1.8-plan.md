## 一、Bug 根因排查结论（已代码级确认）

### BUG-1A 添加资料库'长时间不展示'
**根因（3 个独立问题）**：
1. LibraryScanner.ScanAsync 是全量递归扫描：对每个 CBZ 调用 MakeZipBookAsync → ZipComicSource 打开压缩包读 ComicInfo + 列出全部条目。目录层级越多、文件越多 → 扫描可达数十秒，期间 UI 停在'正在扫描…'（无进度细节），用户以为'没反应/没添加'。
   定位：MainWindowViewModel.AddLibraryAsync；LibraryScanner.ScanDirectoryAsync（每次 MakeZipBookAsync 都开 zip）
2. RescanAsync 只更新 Libraries，不重建 FolderTree → '重新扫描搜出 8 本但什么都不显示'（左侧树旧/空，右侧无数据）。
   定位：MainWindowViewModel.RescanAsync（缺 FolderTreeScanner 调用）
3. LoadSavedLibrariesAsync（启动加载历史库）同样不建 FolderTree → 重启后左侧树空白。
   定位：MainWindowViewModel.LoadSavedLibrariesAsync

**修复方案**：
- 扫描进度反馈：StatusText 动态显示'正在扫描… 已发现 N 本'（ScanAsync 加进度回调或分批统计）
- Rescan / LoadSaved 补齐：重建 FolderTree + 选中根节点 + ShowFolderContents

### BUG-1B 选中深层文件夹后无反应
**根因**：与 BUG-1A-1 同源（扫描慢）。深层=目录多=扫描久。加进度反馈即可消除'无反应'错觉。
**补充**：TryGetLocalPath() 对某些特殊路径可能返回 null → 已判空 return，但无提示。加提示。

### BUG-3 双页点击后无法切回单页 / 配对点击无反应
**根因（两个独立 bug）**：
1. 模式切换循环歧义：ToggleMode 是 单页→双页→滚动→单页 循环，按钮显示当前模式名 → 在双页点按钮实际切到滚动，用户以为'点双页没反应/切不回单页'。
   定位：ReaderViewModel.ToggleMode；按钮 Content={Binding ModeText}
2. 配对/切模式后画面不更新（真 bug）：TogglePairOffset → RebuildLayout 重建 _logical（配对起点变了 → 同 CurrentIndex 的物理页变了）→ LoadCurrentAsync 的竞态防护误杀：
   var cur = _logical[CurrentIndex];   // 新布局的 FirstIndex
   if (cur.FirstIndex != lp.FirstIndex || ...) { Release; return; }  // 与本次解码的旧 lp 不一致 → 丢弃！
   → 新画面从不应用 → '点击配对后没反应'。切模式同样受影响（ViewMode 变 → IsDoublePageShown 变 → 防护丢弃）。
   定位：ReaderViewModel.LoadCurrentAsync（竞态防护段）；RebuildLayout；OnPairOffsetChanged
**修复方案**：
- 模式切换 UI：三独立按钮收进'阅读模式'下拉菜单（见 UI 设计）
- 竞态防护改：引入 _layoutVersion（每次 RebuildLayout/ToggleMode 自增），LoadCurrentAsync 快照版本号，仅版本不同才丢弃（不再对比 FirstIndex）

### BUG-4 无法拖动底部进度条
**根因**：Slider 外层 Border IsHitTestVisible=False → Avalonia 父级命中测试关闭 → 子级 Slider 无法接收鼠标。
   定位：ReaderWindow.axaml 底部进度条 Border
**修复**：去掉 Border 的 IsHitTestVisible=False（用透明背景替代视觉）；Slider 自身命中开启。

## 二、滚动模式问题专项（用户补充，已排查）

### W-1 滚轮翻动卡顿
**根因**：ScrollWebtoonByEvent 每事件调用 ApplyTransform + UpdateWebtoonPages，虚拟化更新每帧做增量增删 + 异步解码排队；事件密集时解码风暴。
**修复**：
- 滚动与渲染分离：滚动只改 _ty（瞬时），虚拟化更新节流（仅在范围真正变化时更新）
- 解码限流：同一时刻最多 N 个 Webtoon 解码任务
- 速度按钮（原'缩放×N'）→ 滚动模式变为'滚动速度'（×0.5/×1/×2），乘到滚动步长

### W-2 Ctrl+滚轮缩放'不锚定焦点 + 同时滚动'
**根因**：
1. ContentScreenRect/EffectiveFocus 语义错：ContentScreenRect() 返回 (tx, ty, baseW×scale, BaseH×scale) —— 这是单页矩形；Webtoon 画布是所有页拼接的总高。鼠标在长画布中部时，EffectiveFocus 把 y clamp 到单页高内 → 焦点算错 → 缩放锚点漂移。
   定位：ReaderWindow.ContentScreenRect / EffectiveFocus；ZoomToFocus
2. 缩放与滚动指令同时触发：ZoomToFocus 内部 Webtoon 分支调用 UpdateWebtoonPages（视觉上像'还在滚动'）；且 _ctrlDown 键盘状态与 e.KeyModifiers 可能不同步。
**修复**：
- Webtoon 模式独立焦点语义：缩放锚定 = 鼠标原始位置（不 clamp 到单页），或 clamp 到画布总范围
- 明确事件路由：Ctrl+滚轮 → 只缩放（e.Handled 后不触发滚动路径）；缩放后仅更新虚拟化，不产生滚动位移

### W-3 所有图片应统一宽度拼接
**根因**：LoadWebtoonImageAsync 每页 Width = ratio_i × BaseH（各自比例）→ 宽度不一，拼接参差；且虚拟化范围计算按 BaseH 统一页高（实际页高应随宽度/比例变化）。
**修复（核心重构）**：
- 统一宽度：画布宽 = WebtoonWidth（= 视口适配宽），每页 Image.Width = WebtoonWidth，Height = WebtoonWidth / ratio_i
- 页位置 = 前缀和：页 i 的 y = Σ(0..i-1 的页高)，不再 i×BaseH → _webtoonOffsets[] 预计算
- 虚拟化范围计算基于前缀和（二分定位可见页）

### W-4 滚动时黑屏
**根因（推断，与 W-3 相关）**：页高用 BaseH 统一假设，但虚拟化范围计算在快速滚动时可能 first>last 提前 return，或先清后建异步空档 → Canvas 空。
**修复**：
- 前缀和定位后范围计算稳定（不再 first>last 早退）
- 保留一帧'旧 Image 不移除直到新页就绪'（先加后删）
- 黑屏保护：滚动后强制至少渲染当前可见页
