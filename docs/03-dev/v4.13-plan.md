## 1. 封面缩略图文件句柄泄漏（问题二，已修复）

- 现象：给文件夹设封面后该文件夹无法移动/删除（`Access to the path ... is denied`），过一阵单独移动又成功
- 根因：`ThumbnailService.GetImageCoverThumbAsync` 用 `Bitmap.DecodeToWidth(File.OpenRead(path), ...)`——**File.OpenRead 的流从未释放**，句柄锁定封面图片及其所在目录；GC 回收前目录不可移动
- 修复：`using (var fs = File.OpenRead(imagePath))` 包住解码；日志实证（MOVE FAIL 前 10 秒刚好设置过该文件夹封面）

## 2. 路径存储改为"库根相对路径"（问题三 A 实施）

### 设计
- `ReadingStateStore.LibraryRoots`（静态，主窗口加载/添加库后 `SetLibraryRoots`）——库根列表
- 所有记录路径（`ReadingState.Path` / `Bookmarks.Path` / `FolderCovers.FolderPath`）**存储时**：
  - `ToStoragePath(abs)`：取**最长匹配库根** → 相对路径（如 `25.08\ちょいぴろ`）；无匹配 → 绝对路径原样（兼容无库场景）
- **读取时**：`FromStoragePath(stored)`：绝对 → 原样；相对 → 遍历库根（具体优先）拼接，**优先返回存在者**，兜底首个候选
- 对调用方透明（ReaderViewModel/MainWindowViewModel 照旧传绝对路径）
- **旧数据迁移**：`MigratePathsToRelative()`（幂等：只动绝对路径记录）——启动加载库后、添加库后各调用一次
- 效果：**整个资源库移动到新位置 + 重新添加为新库 → 封面/阅读进度/书签全部自动匹配**（相对路径不变）
- 已验证（5 项测试）：库移动后进度恢复 / 封面恢复；最长库根匹配；存在者优先解析；旧绝对记录迁移

### 局限（已知）
- 库根**改名/新增子库根**导致同一路径基准变化 → 旧相对键与新基准不一致（迁移只在明显匹配时进行；罕见情形需手动重设封面）
- 同一相对路径在多个库根下都存在时有歧义（取存在者/首候选）

### 数据位置（回答用户问题）
全部在 `%LOCALAPPDATA%\HachimiManga\reading.db`（SQLite 单文件）：
- `FolderCovers（FolderPath=库根相对路径, RelPath=相对该文件夹的图片路径）`
- `ReadingState（Path=书相对路径, 页码/模式/方向）`
- `Bookmarks（Path, 页码）`

- 冲突/失败项汇总显示（不静默）
- 实现依赖：`ReadingStateStore` 增加 `ExportData()/ImportData(json, merge)`；设置页卡片 + 文件对话框

## 4. v4.14 补丁：`.` 冲突修复 + 失效库提示 + 导出/导入（已实施）

### 4.1 库根文件夹设封面"返回再进入一定消失"（用户实例：秘密結社うさぎ = 库根）
- 根因：`ToStoragePath` 把"路径==库根"转成相对路径 **"."**；同级多个库根条目（秘密結社/毎日健康生活/飯食って寝る）**全部存 "."** → 主键互相覆盖；读取时"相对键→绝对路径"反转映射同样把所有 "." 映射到同一个条目 → 其余条目必然拿不到封面
- 修复：
  - `ToStoragePath`：路径 == 库根 → **返回绝对路径**（不再 "."）
  - `LoadFolderCovers`：改**逐条查询**（取消反转映射，杜绝一个存储键对应多个条目的歧义）
  - `MigratePathsToRelative`：**清理 "." 记录**（无法还原归属；那几个库根文件夹的封面需手动重设一次）
  - 文件夹型书的 ReadingState/Bookmarks 同样受益
- 测试：库根自身封面往返 + 多库根共存（`CoverFixAndExportTests.Library_Root_Itself_Covers_Do_Not_Collide`）、`.` 记录清理

### 4.2 启动时失效库路径提示
- `LoadSavedLibrariesAsync` 统计 `libraries.txt` 中不存在的路径 → 状态栏提示"有 N 个资料库路径失效（可能被移动/改名），请重新添加"
- 库改名/搬家后：**重新添加库即可恢复封面/进度/书签**（相对路径存储）；旧失效行无害

### 4.3 导出/导入（设置页「数据管理」卡片，已实现）
- `ReadingStateStore.ExportToJson(path)` / `ImportFromJson(path, overwrite)`
- 导出 JSON：covers（folder=库内相对存储值, image）/ progress（book/page/mode/direction）/ bookmarks；**只含设置不含图片**
- 导入匹配：每条记录按"存储值在当前库根下是否存在"解析（相对 → 遍历库根找存在者；绝对 → 直接校验）→ **库根改名/换名不影响**（不按库名匹配）；未匹配汇总计数
- 合并：`overwrite=false` 已存在跳过（默认），勾选覆盖
- UI：设置→阅读→数据管理：导出按钮（保存对话框）/导入按钮（打开对话框）+ 覆盖勾选 + 结果行
- 测试：库改名后导出→导入全恢复、overwrite=false 跳过、未匹配计数

### 4.4 使用体验
- 库根文件夹（秘密結社等）设封面 → 返回/重启不消失；升级后需重设那 3 个库根文件夹的封面（旧 "." 记录已清理）
- 库改名/搬家 → 重新添加库，封面/进度/书签全恢复；新机器导出导入同样按相对路径找回
